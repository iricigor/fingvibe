FingVibe 1.4 connects people, rooms and devices with a combined People & rooms page, an interactive conceptual Room map, and clearer evidence for related MAC addresses.
It also discovers more service-advertising LAN devices, expands TCP scanning with a separately confirmed full-port scan, and polishes device sorting, Settings, icons and installation.

## Major changes

- **Room map:** a native, read-only view groups the selected network's devices into saved rooms and an unassigned area, highlights the gateway and this computer, and draws conceptual connections to routers and the Internet. Open it from Tools, Network troubleshooting or Rooms; select a room name or device to open its details and return to the same map position and focus. Only online is enabled by default; turning it off reveals other saved devices without rearranging the layout. Connections illustrate organization, not measured physical topology. [#559](https://github.com/iricigor/fingvibe/pull/559), [#566](https://github.com/iricigor/fingvibe/pull/566).
- **People & rooms:** one navigation destination brings both lists together with shared search, separate counts and add actions, and compact short-name badges. Person and room details return to the combined page. [#520](https://github.com/iricigor/fingvibe/pull/520).
- **Broader service discovery:** bounded DNS-SD enumeration resolves advertised service types, including unfamiliar ones. Fresh, validated mDNS or SSDP replies can establish Online presence even when ping and fresh ARP receive no answer. Responders without a MAC remain current-scan rows marked MAC unavailable, not invented saved equipment. A service-discovery icon in Devices opens the new evidence section in Device Details; advertised roles, names, models and manufacturers stay distinct from verified identity. Advertised TCP endpoints count as open only after answering a bounded connection check on the advertising device. [#570](https://github.com/iricigor/fingvibe/pull/570).
- **Expanded TCP scans:** ordinary LAN scans check 17 default ports, and the manual single-device additional scan checks 193 distinct non-default ports. A separate Full TCP port scan attempts ports 1-65,535 only after confirmation on every run, warning about runtime, monitoring and scanning only owned or authorized devices. Progress and discovered open ports appear during the scan; cancellation retains results and marks coverage incomplete. Full and additional scans never run automatically or as LAN-wide scans, and do not scan UDP. [#574](https://github.com/iricigor/fingvibe/pull/574).
- **Device identity evidence:** scans retain protocol-labelled names and supported device identifiers already present in collected replies, with per-value observation times, without changing the chosen display name. Possible matching MAC addresses are suggested from this computer's adapters, shared device identifiers or qualifying current names; reasons are visible and declined pairs are remembered. Suggestions are evidence, not automatic linking, and do not use vendor, nearby IPs or room assignments as proof. [#537](https://github.com/iricigor/fingvibe/pull/537), [#561](https://github.com/iricigor/fingvibe/pull/561).
- **Earlier MAC addresses inline:** expand an existing virtual-device row to see up to three recent earlier MAC addresses, extra search matches and an overflow summary, aligned with the row's device data. The chevron and Left/Right keys control expansion; ordinary row activation still opens details. Expansion survives navigation, sorting and scans during the session, and resets on restart. [#571](https://github.com/iricigor/fingvibe/pull/571).

## Other user-facing changes

- **Device-name sorting:** repeated Name-header activation cycles through ascending and descending with emojis ignored, then ascending and descending with the full name. The Aa indicator identifies emoji-ignoring modes; displayed and saved names do not change, and other columns retain their two-state sorting. [#525](https://github.com/iricigor/fingvibe/pull/525).
- **Settings:** Windows 11-style cards align leading monochrome icons, wrapping summaries and trailing chevrons, with consistent spacing and responsive headers. Existing inline expansion, preferences, keyboard behavior and About/update indicators remain intact. [#534](https://github.com/iricigor/fingvibe/pull/534).
- **Page and tool icons:** a coherent selected icon family appears in navigation, page headers and Tools cards, with matching theme-aware presentation. The published payload includes the icon assets, so distributed builds retain the same icons. This does not replace the Connected home application icon introduced in 1.3. [#519](https://github.com/iricigor/fingvibe/pull/519), [#555](https://github.com/iricigor/fingvibe/pull/555).
- **Installation:** interactive installs and upgrades offer a checked-by-default Start FingVibe choice on the finish screen. The installed app starts only after Finish; clearing the choice or using either silent mode never launches it. Version 1.4 retains the portable ZIP and unsigned per-user Setup installer, with one higher-build 1.3-to-1.4 upgrade check, saved inventory/history/settings preservation and subsequent downgrade rejection. [#533](https://github.com/iricigor/fingvibe/pull/533), [#584](https://github.com/iricigor/fingvibe/pull/584).
- **Downloads:** the README shows an all-time release-asset download badge linked to releases; it counts downloads, not installations or unique users, and adds no application telemetry. [#543](https://github.com/iricigor/fingvibe/pull/543).

## Engineering and contributor improvements

- **Targeted native coverage:** shared analytics and application contracts select all current UI consumers, while reviewed non-native paths avoid unnecessary app publishing and desktop checks. Native test changes still select native validation, and unreviewed paths remain conservative. [#501](https://github.com/iricigor/fingvibe/pull/501), [#503](https://github.com/iricigor/fingvibe/pull/503).
- **Installer validation:** installer checks overlap Core tests using the same published payload; runnable download links and screenshot publication still require successful tests. Only disposable lifecycle fixtures use faster uncompressed packaging; distributed installers retain production compression. [#510](https://github.com/iricigor/fingvibe/pull/510).
- **Maintainable regression modules:** four large test entry scripts now load explicit responsibility-owned modules in their original order, preserving entry points, coverage and dispatch. [#513](https://github.com/iricigor/fingvibe/pull/513).
- **Review handoff:** eligible trusted, same-repository draft PRs can become ready after successful first-attempt PR validation; WIP titles, changed heads, forks and untrusted authors remain excluded. This does not merge PRs or change release policy. [#506](https://github.com/iricigor/fingvibe/pull/506).
- **Release identity:** release versions, tags, app metadata, Setup/ZIP names and release titles advance together to 1.4 with the run-number build component. CI keeps its separate 0.0 identity, and release bodies prepend this summary while retaining automatically generated per-release notes. [#584](https://github.com/iricigor/fingvibe/pull/584).
